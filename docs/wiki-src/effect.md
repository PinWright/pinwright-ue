# effect

Runtime/editor preview helpers for transient visual effects in the active world — debug shapes, Niagara spawning, and cleanup of preview objects. Distinct from `call("niagara")`, which is the persistent-asset authoring surface; never use `effect.*` for Niagara system / emitter / renderer / parameter / module edits.

## Niagara effect systems

`effect.spawn_niagara` requires a real `systemPath` (a `NiagaraSystem` asset path). An empty path returns `INVALID_ARGUMENT`, a missing asset returns `SYSTEM_NOT_FOUND`, and a path to another asset class returns `INVALID_ASSET_TYPE` before any actor is spawned. The target is the active PIE world while PIE is running and the editor world otherwise. A requested `attachToActor` label is resolved in that same world before spawning; a missing parent returns `ACTOR_NOT_FOUND`, and a parent from another world returns `ATTACH_FAILED`, rather than silently creating an unattached or cross-world effect.

Before spawning, the verb uses the same bounded compile wait and engine-readiness predicate as the `niagara` namespace. Because spawning is the demand that on-demand compilation defers to, that wait also drains a compile request the asset only has queued — the state a system is left in when its compile was deferred at load, where nothing is actively compiling and no other verb clears the request. A timed-out, explicitly failed, or engine-unready compile returns `SYSTEM_NOT_COMPILED` with measured `compileStatus`, wait time, pending state, and the compile diagnostics block. `compileStatus` and `outstandingCompilationRequests` are measured with the same predicate the refusal is decided on; the nested `compile` block reports the wider GPU-inclusive queue. That drain is not free, and the verb exposes no `timeoutSeconds` to opt out of it: it can hold the game thread — every other agent on the editor with it — for as long as the compile takes, up to the shared 60 s ceiling. It also has a side effect on the open level, because `UNiagaraSystem::RequestCompile` ends by destructing an `FNiagaraSystemUpdateContext` over the system, which reinitializes every live component using it. Call `niagara.compile_status` first if you need to know whether a spawn will be instant or will compile. Per-script status can remain unverified after on-demand compilation; when `UNiagaraSystem::IsReadyToRun()` is true and the bounded wait is quiet, that diagnostic does not override the runnable engine state. It prepares the system, scale, `autoDestroy`, and requested attachment while automatic component activation is disabled, then registers and activates the component exactly once. Attachment failure returns `ATTACH_FAILED`; a missing component, wrong assigned system, unapplied auto-destroy/attachment state, or `IsActive() == false` returns `EFFECT_NOT_ACTIVE`. Post-spawn failures destroy the new actor through its target world before responding, including for PIE actors.

Success means those states were read back. The response includes the normal actor verification fields plus `systemPath`, `componentPath`, `systemAssigned`, `active`, `autoDestroy`, `autoDestroyMeasured`, `attached`, optional `attachmentParent`, `compileStatus`, `compileWaited`, `compileWaitedMs`, `compileTimedOut`, and `outstandingCompilationRequests`. Optional `rotation`, `scale`, `autoDestroy`, and `attachToActor` control placement and component lifetime. For a purpose-built ribbon/beam spawn use [`niagara.create_ribbon`](niagara.md); to spawn a light use [`lighting.spawn_light`](lighting.md).

If you have no specific system in mind, paste the stock engine template that ships with the Niagara plugin: `/Niagara/DefaultAssets/DefaultSystem`. To find a project-specific one instead, list candidates with `asset.search_assets {"classNames":["NiagaraSystem"]}` and validate with `asset.exists` before passing the path.

## Advance an active effect in bounded steps

Use `effect.advance_simulation` after resolving a placed Niagara actor when you need manual ticks without a capture. Pass `systemName` (or `actorName`) plus optional `steps` (a positive whole number from `1` through `10000`, default `1`) and `deltaTime` (finite, at least `0.0001` seconds, default `0.1`). The product of the actual float delta and the step count may not exceed `60` seconds. Non-finite, non-positive, fractional, or over-limit values are refused with `INVALID_PARAMS` before the actor is resolved; every limit error names the per-step, step-count, and total-duration limits.

On success the response includes `steps`, the actual float `deltaTime` passed to `AdvanceSimulation`, `requestedSeconds` (the requested delta multiplied by the step count), and `simulatedSeconds` (the Niagara system age delta measured around the call). If the measured age falls materially short, the response also includes `stoppedEarly: true` and `stopReason`: `no_controller`, `paused`, `complete`, `no_progress`, or `advanced_less_than_requested`. The verb is deferred to a safe point when a request arrives inside the editor's world tick because Niagara's manual ticks run synchronously on the game thread.

## Capture a short effect at one exact instant

Use `effect.step_and_capture` for a placed Niagara system that may finish between separate RPCs. It composes activation and the open-level capture into one synchronous operation: reset/activate the component, let the viewport warm-up converge while world time still runs, freeze the Niagara actor's world, call `AdvanceSimulation`, draw and read the final frame, then restore the previous world time dilation on every exit path. Exposure is deliberately resolved before the freeze because eye adaptation cannot converge while world time is stopped.

Pass `systemName` (or `actorName`) and optionally `reset` (default `true`), then use one positive time form: `seconds` or whole `frames`; omitting both samples one frame. `deltaTime` is optional and defaults to `1/60`. In seconds mode the verb chooses enough uniform steps to target the requested age without exceeding the requested step delta; for example, `seconds: 0.2` uses twelve approximately 1/60-second steps. Its editor-world camera, output, view-mode, `subject`, `hideEditorSprites`, and `exposure` arguments use the same formats as `render.capture_open_level`; it deliberately does not accept `allowPieWorld`, because the named effect is resolved in the editor world. `seconds` and `frames` together return `INVALID_ARGUMENT`.

Simulation work is bounded: the actual per-step delta must be at least `0.0001` seconds, the call may use at most `10000` steps, and the total simulated duration may be at most `60` seconds. These limits apply in both frames and seconds mode. A seconds request is also rejected when deriving uniform steps would exceed `10000` or reduce the effective per-step delta below `0.0001`. Limit violations return `INVALID_PARAMS` and name all three numeric limits.

The verb returns the normal open-level capture response plus `effect`. `steps` and `deltaTime` are the values actually passed to `AdvanceSimulation`; `requestedSeconds` preserves the requested logical age, while `simulatedSeconds` is the Niagara system age delta measured around the call. The compatible `sampledSeconds` field preserves the same requested logical age and can differ from `simulatedSeconds` when Niagara pauses, completes, or otherwise applies fewer ticks. In that case the block also includes `stoppedEarly: true` and the same `stopReason` categories. The block also records `timeMode`, `exposureSettledBeforeFreeze`, measured activation state when available, and the before/frozen/restored world-time values.

**Submit deferred Niagara render state before drawing.** `AdvanceSimulation` completes the manual game-thread ticks even while world time is frozen, but `UNiagaraComponent::MarkRenderDynamicDataDirty` queues the resulting render data for the world's end-of-frame pass. The capture therefore calls `UWorld::SendAllEndOfFrameUpdates()` before `SceneViewport::Draw()`; `FlushRenderingCommands()` alone cannot submit a world-side queue that was never sent, so hand-driven viewport captures must preserve this ordering.

This is a single-instant placed-world capture. For isolated asset-preview time series use [`render.capture-time`](render.capture-time.md). For how auto and fixed exposure are measured, see [`render.capture-exposure`](render.capture-exposure.md).

## Cross-cluster overlap

Particle authoring helpers such as `effect.add_*` are not part of the persistent Niagara asset workflow. Niagara systems, emitters, renderers, parameters, stack entries, and graph edits go through the read-first `niagara.*` workflow: `asset.dump` or `niagara.inspect`, then one individual `niagara.*` edit RPC, then `niagara.validate`.
