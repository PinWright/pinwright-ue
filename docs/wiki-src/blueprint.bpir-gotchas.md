# BPIR gotchas

These traps span `blueprint.compile_bpir`, `blueprint.insert_bpir_at_node`, `blueprint.insert_bpir_before_node`, and the surrounding compile/decompile cycle. None surface as MCP errors; most appear only at UE compile time or runtime.

## The checklist

- **`compile_bpir` is graph placement, not validation. Always run `blueprint.compile` after.** It only places nodes; UE's BP compiler may still reject enum pin types, delegate self-context, or signature mismatches. Check `compiled` and `status` — do not trust BPIR success alone.
- **Enum pin serialization depends on pin category.** `PC_Enum`, enum-backed `PC_Byte`, and bare byte pins differ. If enum wiring still fails, inspect the exact category before patching defaults; detailed rules are in `call("bpir.instructions")` (§2.11 enum / array / set / map literals).
- **Default `compile_bpir` retries are idempotent through the RPC.** The public handler maps default `mode: "append"` and legacy `mode: "replace"` to one upsert path: matching entries are deleted, then recreated. Use `mode: "extend"` only when intentionally appending to an existing override body.
- **`add_event` then default `compile_bpir` is silently un-undoable; use `mode: "extend"` to keep undo working.** The prototype flow — `blueprint.add_event`, then default `append`/`replace` body compilation — runs Phase 0, which *deletes the `add_event`-created entry* without snapshotting it before re-creating it. `blueprint.undo_last_bpir` then refuses with `UNDO_NOT_REVERSIBLE` because it cannot un-sweep the deletion. The error points *backward* (git / `asset.revert`); for an additive prototype, compile with `mode: "extend"` to skip Phase 0, so `undo_last_bpir` cleanly deletes exactly the created nodes. Start with `extend` when you may undo a body added to a fresh `add_event` entry.
- **Widget `IsVariable` requires a reimport + compile cycle.** `IsVariable=true` in `widget.import_xml` does not immediately make widgets member variables. Reimport the XML **and** call `blueprint.compile` before BPIR can reference `$WidgetName`; one import-and-compile is insufficient when the flag was flipped mid-session.
- **`bind_dispatcher` wires `K2Node_CreateDelegate.self` to Target instead of self.** For a custom event on the *current* widget/actor, the compiler wires the delegate's `self` pin to Target instead of the owning blueprint, so the handler is never found at runtime. After BPIR, inspect the delegate, delete the wrong `self` wire, and rewire it to the correct self-reference.
- **`compile_bpir` cannot create BlueprintNativeEvent overrides.** Attempting to override a `BlueprintNativeEvent` (e.g., `NativeOnInitialized`) creates a standalone function that conflicts with the parent's native implementation. Use the editor's "Override Functions" UI to create the override graph, then populate it with BPIR or manual nodes.
- **`custom_event` listening to a USTRUCT-carrying delegate must declare the param as `const struct<FMyStruct>& Val`.** By-value (`struct<FMyStruct> Val`) passes the BPIR parser, but the pre-save integrity gate catches `IsSignatureCompatibleWithScriptDelegate` mismatch and rolls back with `INTEGRITY_FAILURE: 1 stale reference(s)`. By-ref-without-const (`struct<FMyStruct>& Val`) also fails. This applies to every cross-widget listener binding a dispatcher with a USTRUCT or UObject-ref param.
- **Inherited component-template writes split by inheritance source.** A Blueprint-parent component can be overridden through `blueprint.scs.set_property`; validate on the parent template first, then create/fetch the child `UInheritableComponentHandler` override with `FComponentKey` only for a valid write. A C++-parent component is not an SCS node; use `python.execute` with `CDO.get_component_by_class(...)` and assign on that instance.
- **`$name` can intentionally fall back to a prior `%name` BPIR local.** Use this for direct references and alias RHS forms such as `%alias = $v` when `v` is local, not a Blueprint variable. The compiler resolves through `FCodePinResolver`, cached variable gets, then the block value index; it must not emit orphan `UK2Node_VariableGet` nodes for non-member names.
- **`widget.import_xml` can't resolve some BP widget classes.** It handles `W_TutorialIntroBox` but fails on `W_AnimatedButton`; when import fails for a known-good class, place it manually with `widget.add`.
- **A widget `.uasset` left in a partially-compiled BPIR state can become unloadable.** Orphan `K2Node_CreateDelegate` nodes from a failed/partial BPIR compile can crash `blueprint.inspect`, `compile_bpir`, and `widget.describe` in `ReplaceConvertibleDelegates::FindPinChecked` on load. Delete and recreate the asset; always run `blueprint.compile` after BPIR and fix or roll back before saving.
- **`USTRUCT` rename/restructure is not picked up by hot-reload.** `find_object` and `FJsonObjectConverter` keep seeing the OLD layout until editor restart. Symptom: BPIR compiles fail with `TryCreateConnection failed wiring data <Field> -> <NewType>`. Fix: close UE Editor, reopen, reconnect MCP.
